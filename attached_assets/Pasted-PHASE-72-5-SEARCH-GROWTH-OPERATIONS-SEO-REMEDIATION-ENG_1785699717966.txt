A. SEARCH OPERATIONS AUTOMATION

Add controlled scheduling using the existing Elevate360 job-runner architecture.

Required jobs:

1. Daily GSC synchronization
   - Run once every 24 hours.
   - Reuse the existing DB-enforced single-running-sync guard.
   - Skip safely if a sync is already running.
   - Preserve founder-triggered manual sync.
   - Record every automated attempt in gsc_sync_runs.
   - Use source="scheduled" if the existing enum permits it; otherwise make an additive type-safe change.

2. Weekly SEO audit
   - Run once every seven days.
   - Audit the same approved canonical public routes used by Phase 72.4.
   - Do not audit dashboards, APIs, private routes, or arbitrary external URLs.
   - Preserve deterministic self-fetch behavior.
   - Record audit results using existing SEO audit tables.

3. Failure control
   - No retry storms.
   - Use bounded retries only for transient network, rate-limit, or Google 5xx failures.
   - Do not retry configuration, permission, validation, or unsupported-capability failures indefinitely.
   - Record the final failure category honestly.

B. SEARCH PERFORMANCE CHANGE DETECTION

Compare stored periods without calling Google during dashboard reads.

Required comparisons:

- Latest seven complete days versus previous seven complete days
- Latest 28 complete days versus previous 28 complete days

Detect:

1. Emerging queries
   - Meaningful new impressions or clicks compared with the prior period.

2. Declining queries
   - Material click, impression, CTR, or position deterioration.

3. High-impression, low-CTR queries
   - Minimum data thresholds required.
   - Do not create recommendations from one or two incidental impressions.

4. Near-page-one queries
   - Average positions approximately 8–20.
   - Label this as a prioritization range, not a guaranteed page classification.

5. Landing-page opportunities
   - Pages receiving search impressions but weak engagement or funnel progression.

6. Search-to-revenue opportunities
   - Use existing directional session-level attribution.
   - Preserve the existing disclosure that this is not Google-verified keyword revenue attribution.

7. Technical regressions
   - New metadata, structured-data, canonical, indexability, sitemap, internal-link, or Core Web Vitals issues.
