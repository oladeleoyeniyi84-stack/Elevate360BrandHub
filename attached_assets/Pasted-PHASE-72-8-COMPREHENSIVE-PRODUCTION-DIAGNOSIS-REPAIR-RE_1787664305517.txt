PHASE 72.8 — COMPREHENSIVE PRODUCTION DIAGNOSIS, REPAIR & REGRESSION CERTIFICATION

ENGINEERING SEQUENCE

🟢 1. Diagnose + Build/Fix — Replit Agent
⬜ 2. Review — Founder + Mission Control

PRIMARY OBJECTIVE

Perform a comprehensive, evidence-based diagnostic of the entire Elevate360Official platform and all currently implemented features.

Identify:

* broken functionality;
* silent failures;
* security weaknesses;
* authentication/session issues;
* billing and Stripe defects;
* analytics inconsistencies;
* SEO regressions;
* routing defects;
* API failures;
* database/schema mismatches;
* stale or unsafe code paths;
* broken links;
* mobile/responsive problems;
* accessibility defects;
* performance regressions;
* client/server hydration or rendering issues;
* AI/Concierge failures;
* content-management defects;
* dashboard problems;
* email/notification failures;
* automation/scheduler defects;
* stale environment assumptions;
* duplicate or dead code;
* logging/observability gaps;
* privacy/data-leakage risks;
* production-readiness issues.

Fix all defects that can be safely and objectively verified.

Do not perform speculative rewrites merely because code could be structured differently.

Do not alter product behavior, pricing, copy, UX, architecture, or commercial policies unless required to fix a verified defect.

⸻

OPERATING CONSTRAINTS

This is DIAGNOSE + FIX + TEST ONLY.

DO NOT:

* commit;
* push;
* deploy;
* modify Render configuration;
* rotate secrets;
* change DNS;
* make live Stripe charges;
* create/delete real customer records;
* send real production emails unless using a safe test recipient explicitly authorized;
* cancel subscriptions;
* refund charges;
* delete production data;
* run destructive migrations;
* use db:push against production;
* print environment-variable values;
* expose customer PII;
* expose Stripe secrets;
* expose dashboard PIN;
* expose API keys;
* expose webhook secrets;
* weaken authentication;
* bypass authorization controls to make tests pass.

If a repair requires a production migration, create an idempotent bootstrap script but DO NOT execute it against production.

If any issue cannot be fixed safely in this phase, document it precisely as DEFERRED with severity and recommended remediation.
