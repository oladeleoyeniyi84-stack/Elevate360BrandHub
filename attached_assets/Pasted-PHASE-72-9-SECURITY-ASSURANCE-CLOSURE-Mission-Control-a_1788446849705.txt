C. CUSTOMER-BOUND PAID-CONTENT DELIVERY

This is a primary closure gate.

Audit:

orders
one-time checkout
checkout success
download/delivery routes
thank-you routes
entitlement checks
marketplace delivery
digital products
strategy-session purchase access
any token-based download link

Verify:

* purchase access is bound to authoritative server-side order/customer state
* browser cannot supply arbitrary order ID and access another customer's content
* browser cannot supply arbitrary email to claim another order
* paid flag cannot be forged via query string
* success URL does not itself grant entitlement
* access tokens are unguessable
* expired tokens fail closed
* refunded orders cannot retain paid delivery if policy requires revocation
* canceled/failed payments cannot produce delivery
* server trusts Stripe/webhook state, not browser state
* delivery route enforces ownership or secure possession proof
* IDOR attempts fail

Create explicit adversarial tests.

Examples:

Customer A cannot access Customer B's order.
Random order ID cannot access delivery.
Forged success query cannot unlock content.
Refunded order cannot re-open delivery.
Unknown token returns 404/403.
Expired token returns 403/410 according to policy.

If any defect exists:

write failing test
apply minimal fix
rerun full related suite
